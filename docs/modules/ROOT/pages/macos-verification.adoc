= Verifying macOS support

include::./includes/attributes.adoc[]
:diataxis-type: howto
:categories: miscellaneous

The macOS support of the native executables was verified on an Apple silicon Mac (macOS 27, GraalVM Community
25.4.4.1.1, Quarkus built from the pull request below): the integration tests, every step of this page, and the showcase
(native and JVM runs identical, except the documented native image limits). This page is the check list to repeat it,
for instance with another GraalVM, Quarkus or macOS version, and how to report the results. Each step says what to look
at.

== Setup

Run everything from a Terminal window of a graphical session (not over `ssh`: AWT is headless there), in a directory
outside `~/Desktop`, `~/Documents` and `~/Downloads` (macOS asks for permissions there).

[source,bash]
----
xcode-select --install                     # clang, otool, nm (needed by the native build)
mkdir -p ~/dev && cd ~/dev
curl -LO https://github.com/graalvm/graalvm-ce-builds/releases/download/graal-25.4.4.1.1/graalvm-community-jdk-25i4-25.0.4.1.1_macos-aarch64_bin.tar.gz
tar xzf graalvm-community-jdk-25i4-25.0.4.1.1_macos-aarch64_bin.tar.gz
export JAVA_HOME=$(echo ~/dev/graalvm-community-*/Contents/Home) GRAALVM_HOME=$JAVA_HOME PATH=$JAVA_HOME/bin:$PATH
native-image --version                      # GraalVM CE 25.4 (25.1 or later is needed)
ls -l $JAVA_HOME/lib/shaders.metallib $JAVA_HOME/lib/libawt_lwawt.dylib
xattr -l $JAVA_HOME/lib/libawt.dylib        # nothing ; otherwise: xattr -dr com.apple.quarantine ~/dev/graalvm-community-*
----

Build Quarkus from the pull request https://github.com/quarkusio/quarkus/pull/56979["Enable quarkus-awt on macOS"],
which adds the macOS support to `quarkus-awt` and is not in a Quarkus release yet, then the extensions:

[source,bash]
----
cd ~/dev && git clone --filter=blob:none https://github.com/quarkusio/quarkus quarkus-pr-56979
cd quarkus-pr-56979
git fetch https://github.com/quarkusio/quarkus pull/56979/head:pr-56979 && git checkout pr-56979
git log -1 --format=%h                       # 93fd8e95720, or a later commit of the pull request
./mvnw -Dquickly                             # installs Quarkus 999-SNAPSHOT (tens of minutes)
cd ~/dev && git clone https://github.com/quarkiverse/quarkus-desktop quarkus-desktop
cd quarkus-desktop
./mvnw -B install -DskipTests
./mvnw -B verify -pl awt/deployment,swing/deployment        # the macOS lists exist in this JDK (macEntriesExist)
----

== Integration tests

[source,bash]
----
./mvnw -B verify -Dnative -Dnative.surefire.skip -pl awt/integration-tests,swing/integration-tests \
    -Dquarkus.version=999-SNAPSHOT 2>&1 | tee it.log
----

Windows are shown for a few seconds. Report the test results (and the `RESULT ... FAILED` lines of `it.log`).
`-Dnative.surefire.skip` skips the JVM mode tests, as the continuous integration does: the test framework of a Quarkus
`999-SNAPSHOT` may not match the extensions built against the released Quarkus (the extensions themselves work with
both).

== Probe application

A Swing window with an AWT button and a menu bar, which prints what matters and exits with the code 3 after 5 seconds.
Create `~/dev/macprobe/pom.xml`:

[source,xml,subs=attributes+]
----
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>probe</groupId>
  <artifactId>macprobe</artifactId>
  <version>1.0</version>
  <properties>
    <maven.compiler.release>17</maven.compiler.release>
    <quarkus.version>999-SNAPSHOT</quarkus.version>
  </properties>
  <dependencyManagement>
    <dependencies>
      <dependency>
        <groupId>io.quarkus</groupId><artifactId>quarkus-bom</artifactId><version>${quarkus.version}</version>
        <type>pom</type><scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>io.quarkiverse.desktop</groupId><artifactId>quarkus-desktop-swing</artifactId><version>999-SNAPSHOT</version>
    </dependency>
  </dependencies>
  <build>
    <plugins>
      <plugin>
        <groupId>io.quarkus</groupId><artifactId>quarkus-maven-plugin</artifactId><version>${quarkus.version}</version>
        <extensions>true</extensions>
        <executions><execution><goals><goal>build</goal></goals></execution></executions>
      </plugin>
    </plugins>
  </build>
  <profiles>
    <profile>
      <id>native</id>
      <activation><property><name>native</name></property></activation>
      <properties><quarkus.native.enabled>true</quarkus.native.enabled></properties>
    </profile>
  </profiles>
</project>
----

and `~/dev/macprobe/src/main/java/probe/MacProbe.java`:

[source,java]
----
package probe;

import java.awt.*;
import javax.swing.*;

import io.quarkus.runtime.ApplicationLifecycleManager;
import io.quarkus.runtime.Quarkus;
import io.quarkus.runtime.QuarkusApplication;
import io.quarkus.runtime.annotations.QuarkusMain;

@QuarkusMain
public class MacProbe implements QuarkusApplication {

    @Override
    public int run(String... args) {
        System.out.println("run() on " + Thread.currentThread().getName() + " parked="
                + System.getProperty("io.quarkiverse.desktop.main-thread-parked"));
        EventQueue.invokeLater(() -> {
            JFrame frame = new JFrame("Mac probe");
            JMenuBar bar = new JMenuBar();
            JMenu menu = new JMenu("File");
            menu.add(new JMenuItem("Item"));
            bar.add(menu);
            frame.setJMenuBar(bar);
            frame.add(new JButton("Swing"), BorderLayout.NORTH);
            frame.add(new java.awt.Button("AWT"), BorderLayout.CENTER);
            frame.add(new JTextField("text"), BorderLayout.SOUTH);
            frame.pack();
            frame.setVisible(true);
            GraphicsConfiguration gc = frame.getGraphicsConfiguration();
            System.out.println("headless=" + GraphicsEnvironment.isHeadless()
                    + " laf=" + UIManager.getLookAndFeel().getClass().getName()
                    + " multiClick=" + Toolkit.getDefaultToolkit().getDesktopProperty("awt.multiClickInterval")
                    + " control=" + SystemColor.control + " gc=" + gc.getClass().getName()
                    + " scale=" + gc.getDefaultTransform().getScaleX()
                    + " threads=" + Thread.getAllStackTraces().keySet().stream().map(Thread::getName).sorted().toList());
        });
        new java.util.Timer(true).schedule(new java.util.TimerTask() {
            @Override
            public void run() {
                Quarkus.asyncExit(3);
            }
        }, 5000);
        Quarkus.waitForExit();
        return ApplicationLifecycleManager.getExitCode();
    }
}
----

== Checks

. *Build*: `cd ~/dev/macprobe && mvn -B package -Dnative 2>&1 | tee build.log`
* `grep -o "J-Dio.quarkiverse.desktop.awt.macos.park-main-thread=true" build.log` finds it.
* `unzip -l target/*-native-image-source-jar/lib/io.quarkus.quarkus-awt-*.jar | grep -E "PlatformGraphicsInfo_Mac|LWCToolkit|CGraphicsEnvironment|PlatformPrinterJobProxy"`
prints nothing (the substitutions that force headless AWT are removed).
* `ls target/*.dylib` lists at least `libawt`, `libawt_lwawt`, `libosxapp`, `libosxui`, `libfontmanager`, `libfreetype`,
`libjavajpeg`, `liblcms`, `libmlib_image`, `libjava` and `libjvm`.
* `otool -L target/*-runner | grep CoreFoundation` finds it; `otool -l target/*-runner | grep -A2 LC_RPATH` shows
`@loader_path`.
* `otool -l target/*-runner | grep -A4 LC_BUILD_VERSION` shows the `minos` and `sdk` versions of
`otool -l $JAVA_HOME/bin/java` (for instance 11.0 and 14.5), not the version of the Xcode tools.
* `nm -u target/libosxui.dylib | grep -E '_(JNU_|JVM_|jio_)'`: each symbol must be in
`nm -gU target/libjava.dylib target/libjvm.dylib`.
. *Run*: `./target/*-runner; echo $?`: a window appears, then the exit code is `3`. Expected output:
* `run() on main parked=true`;
* `headless=false laf=com.apple.laf.AquaLookAndFeel`;
* `multiClick` is the double click interval of the system settings, not `500`;
* `gc=sun.java2d.metal.MTLGraphicsConfig`, and `scale=2.0` on a Retina display;
* `AppKit Thread` among the threads (and no `Cocoa Run Loop`: AWT renamed the first thread);
* a Dock icon, the application name in the menu bar, and the AWT button drawn by Aqua
(`lsappinfo info -only name,applicationtype $(lsappinfo find pid=$(pgrep -x macprobe-1.0-runner))` shows the name and
the `Foreground` type while the window is shown).
. *Threads*: while the window is shown, `sample $(pgrep -f macprobe) 2 -file /tmp/sample.txt`. The
`com.apple.main-thread` must show `CFRunLoopRun`, then `+[AWTStarter starter:headless:]`,
`+[NSApplicationAWT runAWTLoopWithApp:]` and `-[NSApplication run]`. No thread may wait in `_NSThreadPerformInfo wait`.
. *Diagnostics*: `JNU_APPKIT_TRACE=1 ./target/*-runner 2>&1 | grep -E "Bad JNI lookup|Exception"` prints nothing.
. *Metal*: `./target/*-runner -Dsun.java2d.metal=True` prints `Metal pipeline enabled`. Delete
`$TMPDIR/quarkus-awt-tmp-fonts/lib/shaders.metallib` and run again: it is written again, and Metal is used.
. *Exit paths*: change the probe to close with `frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE)` (and no timer):
closing the window exits with `0`; ⌘Q exits with `0`; an exception thrown by `run()` exits with `1`; Ctrl-C in the
terminal runs the shutdown hooks (exit code 130; a process started in the background by a script ignores SIGINT, as with
the `java` launcher: use `kill -TERM`, exit code 143). The message `System.exit(...) did not complete within ... ms : halting` must never
appear: note how long the exit takes.
. *Headless*: `./target/*-runner -Djava.awt.headless=true` does not hang (`headless=true`, no window).
. *Negative control*: `mvn -B package -Dnative -Dquarkus.native.additional-build-args=-H:+RunMainInNewThread`: the build
logs a warning, the executable prints a warning, and hangs at the first window (this proves the diagnosis).
. *Launcher parity*: run from the terminal with and without `-Dsun.java.launcher=SUN_STANDARD`, then build with
`-Dquarkus.desktop.awt.macos.info-plist=true` (`otool -s __TEXT __info_plist target/*-runner` shows it). Compare the
Dock icon, the activation of the window, and the microphone permission prompt
(`AudioSystem.getTargetDataLine(new AudioFormat(44100, 16, 1, true, false))`).
. *Showcase*: the section "Verifying on macOS" of the README of the Quarkus Desktop showcase (a Quarkus application
that runs every feature of AWT and Swing in JVM mode and as a native executable, and compares them, including the macOS
pages) is the next step.

== Reporting

Send (or attach to an issue of the project) for each step: passed or failed, with the output of the failing ones, and:

* `build.log`, `it.log`, the output of the probe runs, and `/tmp/sample.txt`;
* `sw_vers`, `uname -m`, `native-image --version`, and the Quarkus commit (`git -C ~/dev/quarkus-pr-56979 rev-parse HEAD`);
* the `comparison/` directory, the `logs-*/` directories, `hang-sample.txt` and `native-artifacts.txt` of the showcase.

A failure with a missing registration (`Bad JNI lookup`, `NoSuchMethodError`, `ClassNotFoundException`,
`MissingReflectionRegistrationError`) is fixed in the `MAC_` lists of `AwtClassesAndResources` or
`SwingClassesAndResources`: the showcase `--trace` run gives the metadata to add (`tools/MetadataDiff.java`).
